# Кетсаль · учёт клиентов: что делать без разработчика

Инструкция на случай, когда разработчик недоступен: перенос на другой хостинг, сбои Яндекс Диска, смена аккаунта или облака. Рассчитана на человека, который умеет ставить программы и запускать команды. Там, где нужен программист, это сказано прямо.

Для ежедневной работы и обычных проблем есть [памятка мастеру](pamyatka.md).

## Коротко: насколько это сложно

| Что случилось | Сложность | Кто справится | Раздел |
|---|---|---|---|
| Сайт на GitHub не открывается день-два | Ничего делать не нужно: установленное приложение работает | Мастер | 3 |
| Нужен другой хостинг | Просто: около часа, код менять не нужно | Тот, кто запустит несколько команд | 4 |
| «Нет сети» или сбой Яндекс Диска | Обычно ничего делать не нужно, приложение повторит само | Мастер | 5 |
| Нет доступа к Яндекс ID или нужен другой аккаунт | Просто: около часа, нужна резервная копия | Мастер | 6 |
| Удалено приложение на oauth.yandex.ru | Просто: регистрация, одна строка в коде, сборка | Тот, кто запустит несколько команд | 7 |
| Яндекс Диск надо заменить другим облаком | Сложно: нужен новый код | Программист | 8 |

**Главное: данные не привязаны к хостингу.** На хостинге лежит только программа. Данные лежат на самих устройствах и зашифрованной копией на Диске. Сломался хостинг — данные целы. Сломался Диск — данные целы на устройствах. Опасна только потеря всего сразу: устройств, Диска и резервных копий, либо пароля вместе с ключом восстановления.

## 1. Что держать под рукой уже сейчас

Подготовьте заранее, пока всё работает:

- [ ] **Мастер-пароль** и **ключ восстановления.** Без них данные не откроет никто. Храните отдельно от телефона.
- [ ] **Вход в Яндекс ID салона** (логин, пароль, способ подтверждения). Через него идут Диск и настройки на oauth.yandex.ru.
- [ ] **Вход в GitHub**, аккаунт `VOA-app`. Там код: https://github.com/VOA-app/ketsal-crm
- [ ] **Резервная копия** `.ketsal` не старше месяца, вне телефона: на компьютере или флешке. Она открывается тем мастер-паролем, что был в момент её создания, или ключом восстановления, поэтому после смены пароля сделайте новую.
- [ ] **Копия кода** вне GitHub: папка «Приложение для учета клиентов» на компьютере. Раз в несколько месяцев обновляйте её архивом.

## 2. Как всё устроено

| Часть | Где лежит | Что в ней |
|---|---|---|
| Программа | GitHub Pages: https://voa-app.github.io/ketsal-crm/ | Только файлы приложения, без данных. Собирается из репозитория при каждой публикации |
| Данные на устройстве | В браузере устройства (IndexedDB), отдельно для каждого значка и адреса | Вся база и фото, зашифрованы |
| Данные в облаке | Яндекс Диск → «Приложения» → папка приложения | `vault.json`, `catalog.enc`, `shards/`, `blobs/`, `thumbs/`. Всё зашифровано, кроме `vault.json` (в нём зашифрованный ключ и параметры пароля) |
| Вход в Яндекс | Приложение на oauth.yandex.ru, ClientID в `src/config.ts` | Права только на папку приложения. Секретов нет: ClientID публичный |

Приложение общается с Диском напрямую из браузера. Своего сервера нет, платить или продлевать там нечего.

## 3. Сайт на GitHub недоступен

**Что произойдёт.** Установленное приложение продолжит работать: его файлы хранятся на устройстве. Синхронизация идёт напрямую с Яндексом и от GitHub не зависит. Не получится только установить приложение на новое устройство и получить обновление.

**Что делать.** Если сайт не вернулся за несколько дней или новое устройство нужно срочно, переходите к разделу 4.

## 4. Перенос на другой хостинг

Подойдёт любой хостинг статических файлов с **HTTPS**: обычный виртуальный хостинг, объектное хранилище со статическим сайтом, Netlify, Cloudflare Pages, другой аккаунт GitHub. Сервер с программами и база данных не нужны. Без HTTPS приложение работать не будет: браузер отключит шифрование и service worker.

**Совет: свой домен.** На своём домене (например, `crm.studio.ru`) следующие переезды пройдут незаметно: хостинг сменится, а адрес нет. Устройствам не придётся ни входить заново, ни пересобирать быстрый вход.

### Шаг 1. Установить программы

Нужны [Git](https://git-scm.com/) и [Node.js](https://nodejs.org/) версии 24.

### Шаг 2. Получить код

Если GitHub работает:

```bash
git clone https://github.com/VOA-app/ketsal-crm.git
```

Если нет, возьмите папку `ketsal-crm` из копии проекта. Дальше все команды выполняются в этой папке:

```bash
cd ketsal-crm
```

```bash
npm ci
```

Проверка, что всё цело (должно быть без ошибок):

```bash
npm test
```

### Шаг 3. Собрать приложение под новый адрес

`BASE` — это путь на сайте, начинается и заканчивается косой чертой:

| Адрес приложения | BASE |
|---|---|
| `https://crm.studio.ru/` | `/` |
| `https://studio.ru/crm/` | `/crm/` |

**PowerShell** (Windows):

```powershell
$env:BASE='/crm/'; npm run build
```

**Git Bash** (Windows; без `MSYS_NO_PATHCONV=1` путь исказится):

```bash
MSYS_NO_PATHCONV=1 BASE=/crm/ npm run build
```

**macOS, Linux:**

```bash
BASE=/crm/ npm run build
```

Появится папка `dist`. Это и есть весь сайт.

### Шаг 4. Загрузить на хостинг

Скопируйте **содержимое** папки `dist` в нужное место на хостинге: `index.html` должен открываться по адресу приложения. Специальные настройки сервера не нужны.

Откройте адрес в браузере на компьютере. Должен появиться первый экран «Карты клиентов студии» или экран входа. Белый экран почти всегда означает неверный `BASE`, см. раздел 9.

### Шаг 5. Разрешить новый адрес в Яндексе

1. Войдите на https://oauth.yandex.ru под Яндекс ID салона и откройте приложение.
2. В **Redirect URI** добавьте адрес приложения **точно**, с косой чертой в конце, например `https://studio.ru/crm/`. Старые адреса пока не удаляйте.
3. Сохраните.

### Шаг 6. Перевести устройства

У нового адреса на устройстве своё пустое хранилище, поэтому данные придут с Диска.

1. На старом значке дождитесь «Синхронизировано» без строки «Ждут загрузки». **Сделайте резервную копию.**
2. На iPhone откройте новый адрес в Safari → «Поделиться» → «На экран Домой».
3. Новый значок → «Начать» → «Войти через Яндекс» → **тот же мастер-пароль**.
4. Включите быстрый вход заново: Face ID и код привязаны к адресу.
5. Проверьте клиентов и несколько фото. Оригиналы фото скачиваются при первом открытии.
6. Только после этого удалите старый значок. На компьютере то же самое через закладку на новый адрес.

### Шаг 7. Настроить обновления

Теперь новая версия — это повтор шагов 3–4. Установленные приложения сами покажут «Доступна новая версия → Обновить».

Адрес приложения упомянут в памятке (`docs/pamyatka.md`, третья строка). Исправьте его перед сборкой.

**Если остаётесь на GitHub, но в другом аккаунте:** сделайте копию репозитория, в «Settings → Pages» выберите Source: **GitHub Actions** и замените `/ketsal-crm/` на новый путь в `.github/workflows/pages.yml` и в `vite.config.ts` (`navigateFallbackDenylist`). Публикация пойдёт сама при каждом `git push`. Шаги 5–6 всё равно нужны: адрес другой.

## 5. Сбой Яндекс Диска или «Нет сети»

Сначала нажмите на облачко в «Клиентах» и прочитайте статус и строку «Подробности». Изменения при этом сохранены на устройстве и никуда не пропадут.

| Что написано | Что это значит | Что делать |
|---|---|---|
| «Нет сети» и `Load failed` или `Failed to fetch` | Нет связи с Яндексом | Проверить интернет. Выключить VPN или добавить Яндекс в его исключения |
| «Яндекс Диск сейчас не отдаёт файлы» | Сбой у Яндекса, сервер отвечает ошибкой | Подождать. Приложение повторит само |
| «Часть файлов на Диске не скачивалась… данные отправлены заново» | Был сбой у Яндекса, приложение его обошло | Ничего. Откройте второе устройство, правки сольются |
| «Нужно снова войти в Яндекс» | Вход истёк (живёт около года) или был отозван | Нажать «Войти» |
| «Данные на Диске старее…» | На Диске версия старше, чем видело устройство: откат или подмена | Сделать резервную копию на этом устройстве, синхронизацию не форсировать, см. ниже |
| «Файл на Диске повреждён или подменён» | Файл не прошёл проверку шифрования | То же |
| «На Диске другое хранилище» | В папке данные другого хранилища | Проверить, тот ли аккаунт Яндекса. Ничего не удалять |

**Как отличить сбой Яндекса от проблемы в приложении:**

1. Откройте https://disk.yandex.ru, папку «Приложения», и попробуйте скачать `catalog.enc`. Не скачивается — проблема у Яндекса.
2. На компьютере: F12 → вкладка Console. Запись о `downloader.disk.yandex.ru` с кодом 500 означает сбой Яндекса. Именно так выглядела авария 3 ноября 2026 года.

**Если Диск сломан надолго.** Работать можно: приложение на устройстве полноценное, без Диска нет только обмена между устройствами. Регулярно делайте резервные копии. Если нужно другое хранилище, переходите к разделу 6.

**Откат или подмена на Диске.** Синхронизация остановлена, чтобы не смешать данные. Данные на устройстве целы. Сделайте копию, затем перейдите на новый чистый аккаунт или папку по разделу 6: там данные устройства станут основными.

## 6. Перейти на другой аккаунт Яндекса

Подходит, если потерян доступ к Яндекс ID, закончилось место или папка на Диске испорчена. Код менять не нужно: войти в приложение можно под любым Яндекс ID.

Этот путь переносит и фото. Простая смена аккаунта на том же устройстве фото не перенесла бы: приложение считает их уже загруженными.

1. На устройстве с самыми полными данными: «Ещё → Резервная копия и выгрузка → Сохранить копию». Если приложение предупредило, что часть фото не вошла, запомните это: их файлов не было ни на устройстве, ни на доступном Диске.
2. Сохраните файл `.ketsal` вне приложения: в «Файлы» или на компьютер. Проверьте, что он на месте.
3. Заведите новое хранилище одним из способов:
   - **добавьте новый значок** с другого адреса (раздел 4), старый пока не трогайте;
   - **или сотрите данные на этом устройстве:** «Настройки → Выйти и стереть данные с устройства». Делайте это, только когда копия точно сохранена.
4. Откройте приложение → «Войти через Яндекс» → **новый Яндекс ID**. Папка там пустая, приложение предложит создать хранилище.
5. Придумайте мастер-пароль и **сохраните новый ключ восстановления**. Старый ключ подходит только к старым копиям.
6. «Ещё → Резервная копия и выгрузка → Восстановить из копии» → файл → **пароль той копии** (или её ключ восстановления) → «Заменить всё» и слово «заменить». Фото перешифруются и встанут в очередь на Диск.
7. Дождитесь «Синхронизировано» без строки «Ждут загрузки».
8. На остальных устройствах: сотрите данные (или поставьте новый значок) и войдите под новым Яндекс ID с новым паролем.
9. Убедившись, что всё на месте, **удалите старую папку** на прежнем Диске, если он ещё доступен. Удаление карт по просьбе клиентов до неё уже не дойдёт, а требования к персональным данным никто не отменял.

## 7. Заново зарегистрировать приложение в Яндексе

Нужно, если приложение на oauth.yandex.ru удалено или недоступно: вход выдаёт ошибку про `client_id`.

1. На https://oauth.yandex.ru создайте приложение: тип для веб-сервисов, Redirect URI — адрес приложения.
2. Права: только **«Доступ к папке приложения на Диске»** (`cloud_api:disk.app_folder`).
3. Скопируйте **ClientID**. **Client secret нигде не нужен и никому не передавайте.**
4. Замените значение в `src/config.ts` (`YANDEX_CLIENT_ID`) и соберите заново (раздел 4, шаги 3–4).

**Важно:** у нового приложения **новая папка** на Диске, старая не подхватится. Поэтому дальше действуйте по разделу 6 с шага 1. Резервную копию сделайте **до** публикации новой сборки.

## 8. Заменить Яндекс Диск другим облаком (для программиста)

Обычному пользователю это не сделать. Для программиста задача небольшая: код хранения отделён от остального приложения. Шифрование, слияние и формат файлов менять не нужно.

**Сначала проверьте облако.** Главное условие: API должен работать **напрямую из браузера**, то есть разрешать CORS для адреса приложения на всех запросах, включая скачивание и загрузку, а вход должен обходиться без секрета в коде (OAuth + PKCE). Если этого нет, понадобится маленький прокси, через который пойдёт уже зашифрованное. Проверить можно по образцу `spikes/index.html`. Учитывайте требование хранить данные в РФ (SPEC §1.3).

**Что написать и поменять:**

| Что | Где |
|---|---|
| Новый адаптер с интерфейсом `StorageAdapter` | `src/sync/<имя>Adapter.ts`, образец — `yandexDiskAdapter.ts` |
| Выбор адаптера | `remote()` в `src/sync/service.ts` |
| Вход и получение токена | `src/auth/` (образец — `yandex-oauth.ts`), `src/config.ts`, `init()` в `src/app/store.ts` |
| Разрешённые адреса | `connect-src` в CSP, `vite.config.ts` |
| Тексты про Яндекс | `src/i18n/ru.ts` (`onb`, `sync`), `docs/pamyatka.md` |

Интерфейс (`src/sync/adapter.ts`), пути относительно папки приложения:

```ts
interface StorageAdapter {
  getMeta(path: string): Promise<RemoteMeta | null>; // null — файла нет; sha256 желателен, но не обязателен
  read(path: string): Promise<Uint8Array | null>; // null — файла нет
  write(path: string, data: Uint8Array): Promise<void>; // перезапись; папки создавать при необходимости
  remove(path: string): Promise<void>; // файла нет — не ошибка
  list(dir: string): Promise<{ name: string; size: number; modified: string }[]>; // вся папка; modified — ISO
}
```

Ошибки адаптера определяют, что увидит пользователь:

| Ошибка | Когда |
|---|---|
| `OfflineError` | Сервер не ответил. «Нет сети» |
| `AuthError` | Вход недействителен. «Нужно снова войти» |
| `UnavailableError` | Файл есть, но сервер его не отдаёт. Движок обходит это сам |
| `RemoteError` | Прочие ответы с ошибкой |

**Правила** (`CLAUDE.md`): в `write` попадает только шифротекст и `vault.json`; `fetch` разрешён только в `src/sync/*Adapter*` и `src/auth/`; новые зависимости — по согласованию. В адаптер не должны попадать токены в логах и ссылки с данными аккаунта в текстах ошибок (см. `offline()`).

**Проверка.** Логику движка покрывают тесты на `MockAdapter` (`npm test`). Новый адаптер проверьте вручную на двух устройствах: создание, подключение второго, правки с обоих, фото, удаление. Данные переносятся по разделу 6: копия из старой версии, восстановление в новой.

## 9. Если что-то пошло не так

| Признак | Причина | Что делать |
|---|---|---|
| Белый экран, в консоли 404 на файлы `assets/…` | Неверный `BASE` | Собрать заново с правильным путём |
| Яндекс пишет про `redirect_uri` | Адреса нет в настройках или он отличается | Добавить точный адрес с косой чертой. Открывать приложение по адресу без `index.html` |
| Яндекс пишет про `client_id` | Приложение удалено | Раздел 7 |
| В консоли `Refused to connect… Content Security Policy` | Яндекс начал использовать новый адрес серверов | Добавить его в `connect-src` в `vite.config.ts`, собрать заново |
| Новая версия не появляется | Старая ещё в кэше | Закрыть и открыть приложение, нажать «Обновить» |
| «Приложение уже открыто» | Открыто в другой вкладке | Закрыть лишнее, обновить страницу |
| Face ID не предлагается на новом адресе | Он привязан к адресу | Включить заново в настройках |
| Новое устройство, а Яндекс не работает вообще | Сейчас первый запуск возможен только со входом в Яндекс | Пока есть хоть одно рабочее устройство, продолжайте на нём и делайте копии. Войти можно и под другим Яндекс ID (раздел 6). Если Яндекс недоступен совсем, нужен программист: разрешить запуск без Диска в `src/app/screens/Onboarding.tsx` |

## 10. Крайний случай: достать данные

- **Приложение работает:** «Резервная копия и выгрузка → Выгрузка в Excel» → «Всё с фото (ZIP)». Получите таблицы CSV и папки с фото. Файл **не зашифрован**: храните надёжно, удалите после использования.
- **Приложение не открывается, но есть копия `.ketsal` или файлы с Диска:** соберите приложение из кода (раздел 4, можно на компьютере: `npm run preview`) и восстановите копию. Формат открытый и описан в `SPEC.md` (§5, §6.2, §9.1), шифрование стандартное (AES-256-GCM, PBKDF2-SHA256), поэтому программист может расшифровать файлы и без приложения. Нужен мастер-пароль или ключ восстановления.
- **Нет ни пароля, ни ключа восстановления:** данные не восстановить никому. Так задумано.

## 11. Передать проект другому разработчику или ИИ-помощнику

Всё нужное лежит в репозитории: `SPEC.md` (полное описание и журнал решений), `CLAUDE.md` (правила разработки), `docs/crypto-review.md` (проверка шифрования). Состояние проекта — в `CLAUDE.md` в корне папки проекта на компьютере.

Первое сообщение помощнику может быть таким:

> Это приложение «Кетсаль · учёт клиентов». Прочитай CLAUDE.md, SPEC.md и docs/perenos.md. Задача: <что нужно>. Данные клиентов зашифрованы, правила безопасности из CLAUDE.md нарушать нельзя. В чат не присылаю пароли, токены и client secret.

Не передавайте никому мастер-пароль и ключ восстановления: для работы над кодом они не нужны. Проверяйте всё на демо-версии или тестовом хранилище, а не на рабочей базе.

## 12. Что проверено, а что нет

**Проверено 5 ноября 2026 года:** чистая копия кода с GitHub собирается и проходит все тесты; сборка под адрес `/crm/` работает на обычном веб-сервере на компьютере, с установкой service worker и памяткой; при отключённом сервере приложение открывается из кэша; серверы Яндекса разрешают запросы с другого адреса сайта (проверка заголовков, не полный вход). Логика разделов 5 и 6 покрыта автотестами, сбой Яндекса случился и был пройден на настоящем iPhone 3 ноября 2026 года.

**Не проверялось вживую:** настоящий переезд на чужой хостинг и домен с входом в Яндекс, переход на другой Яндекс ID (раздел 6), новая регистрация приложения (раздел 7).

**Поэтому полезна репетиция** раз в год или перед полным переходом с бумаги: выложите сборку на тестовый адрес, войдите под запасным Яндекс ID, восстановите резервную копию и посмотрите, всё ли на месте. Это около часа, зато инструкция будет проверена на ваших аккаунтах до того, как она понадобится.
