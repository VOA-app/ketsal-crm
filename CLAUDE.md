# CLAUDE.md — «Кетсаль · учёт клиентов»

Учёт клиентов мастера перманента и камуфляжа студии «Кетсаль»: PWA для iPhone, E2E‑шифрование, синхронизация через Яндекс Диск, хостинг на GitHub Pages.
Модель данных фиксированная (SPEC §4): клиенты, процедуры, справочники. Хранение и синхронизация работают с «конвертами» записей и не знают предметной области.
**Полная спецификация — `SPEC.md`. Читай нужный раздел перед началом каждой задачи.**
**Эталон экранов, текстов и логики — `prototype/`** (утверждён мастером). Не придумывай поведение заново: переноси из прототипа. Сам прототип не правь.

## Общение
- Отвечай пользователю на русском. Код, идентификаторы и коммиты — на английском.
- Все строки интерфейса — только в `src/i18n/ru.ts`, никаких захардкоженных текстов в компонентах.

## Жёсткие правила безопасности (нарушать нельзя)
1. **Открытый текст не уходит с устройства.** В `StorageAdapter.write` и в IndexedDB попадают только результаты `crypto/aead.encrypt`. Единственное исключение — `vault.json` (SPEC §5.3).
2. **Web Crypto вызывается только в `src/crypto/`.** Остальной код использует его API.
3. **Сеть — только в `src/sync/*Adapter*` и `src/auth/`.** Никаких других `fetch`.
4. **Никаких внешних скриптов, CDN, шрифтов с чужих доменов, аналитики, трекеров.** Шрифты бренда лежат в `public/fonts/`. Новую npm‑зависимость согласуй с пользователем и объясни, зачем она.
5. **Никогда не логировать** пароли, ключи, токены, расшифрованные данные. Никаких `console.log` с данными в прод-сборке.
6. **IV всегда случайный** из `crypto.getRandomValues`, 12 байт, новый на каждое шифрование. AAD — строго по SPEC §5.2.
7. **Ключи — `CryptoKey` с `extractable: false`**, где это возможно. Не хранить сырые байты ключей в состоянии React или Zustand.
8. **Не придумывать свою криптографию:** только AES‑256‑GCM, PBKDF2‑SHA256, HKDF, как в SPEC. Изменения параметров — только через версию KDF и миграцию.
9. **Фото всегда проходят `media/process.ts`** (перерисовка удаляет EXIF и GPS) до шифрования.
10. **CSP из SPEC §11** не ослаблять (`unsafe-inline`, `unsafe-eval` запрещены).
11. **Секреты в репозиторий не попадают.** Репозиторий открытый: только ClientID Яндекса (он публичный), никаких токенов, client secret и паролей — ни в коде, ни в `.env`, ни в тестах.

## Персональные данные клиентов (SPEC §1.3)
- **В тестах, фикстурах, скриншотах и демо — только выдуманные данные** (демо‑набор из прототипа). Реальные данные клиентов в репозиторий не попадают никогда.
- Телефоны, имена и заметки не выводятся в логи, сообщения об ошибках и тексты коммитов.
- Анкета здоровья не показывается в списках и таблицах, в карте — только под «Показать», из открытого экспорта исключается по умолчанию.
- «Удалить карту полностью» (purge) физически удаляет фото клиента с Диска. Tombstone `purged` не содержит `v` и побеждает любые правки при слиянии.

## Архитектурные правила
- Слои: `app` (UI) → `domain` / `db` / `sync` → `crypto`. UI не обращается к `crypto` и `sync` напрямую, только через store и repo.
- Хранилище только через интерфейс `StorageAdapter`. Для тестов есть `MockAdapter`.
- Предметные правила (напоминания, предупреждения, «повторить», отчёты) — чистые функции в `domain/` без I/O, покрытые тестами на фиксированном «сегодня».
- Слияние (`sync/merge.ts`) — чистые функции без I/O, покрытые тестами (коммутативность, идемпотентность, tombstones).
- Форматы на диске версионируются. Любое изменение формата делается через миграцию и новую версию.

## Бренд (SPEC §10.2)
- Цвета — только токены из `design/tokens.css`. Алый `#D00405` — только точки‑маркеры и число на значке.
- Cormorant Garamond — только заголовки от 24 px, всё остальное — Onest. Подключать оба сабсета woff2 (latin + cyrillic) с unicode‑range, иначе пропадут цифры.
- Латиница QUETZAL не используется нигде. Текст не кладётся поверх фото.

## Обязательные тесты
- `crypto`: roundtrip; неверный пароль; изменение 1 байта шифротекста, чужой AAD, откат ревизии → ошибка; смена пароля сохраняет доступ; recovery key работает.
- `merge`: пополевой LWW, удаление против правки, `purged` против офлайн‑правки, дубль номера карты, одинаковый результат при любом порядке слияния.
- `domain`: окна коррекции (скоро / пора / просрочена / перестаёт), обновление только для зон с `update`, дни рождения (29 февраля), «давно не были», все виды предупреждений, «повторить как в прошлый раз» (тип, услуга, действующая партия), скидка в % и ₽, сертификат, отчёты за месяц и год.
- `phone` и поиск: нормализация `8 917…`, `+7(917)…`, `917…` → `+7917…`; поиск по фрагменту цифр и номеру карты.
- e2e: онбординг → найти или создать клиента → процедура с фото «до» → блокировка → разблокировка → процедура видна в истории, итоги обновились.

## Специфика iPhone (Safari, standalone PWA)
- Тестировать в режиме «На экран Домой», а не только во вкладке Safari: у standalone отдельное хранилище.
- `viewport-fit=cover` + `env(safe-area-inset-*)`; тач‑цели ≥ 44 pt; у инпутов `font-size` ≥ 16px, иначе iOS зумит страницу.
- Памяти мало: фото обрабатывать по одному, освобождать `ImageBitmap.close()`, вызывать `URL.revokeObjectURL`.
- На старте вызывать `navigator.storage.persist()`.

## Чек‑лист ревью криптографии (этап 7)
- [ ] Нет повторного использования IV (grep по `iv`, тест на 10⁵ шифрований без коллизий в рамках сессии).
- [ ] AAD везде задан и совпадает при шифровании и расшифровке.
- [ ] Нет путей, по которым открытый текст попадает в IndexedDB, localStorage или сеть (grep по `put(`, `setItem`, `fetch`).
- [ ] Ключи неизвлекаемые, после блокировки удаляются из памяти.
- [ ] Ошибки расшифровки не глотаются молча, а показываются пользователю.
